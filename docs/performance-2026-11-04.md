# 博客图片传输优化

本次优化沿用 Vercel 和现有深圳 OSS，不修改域名、DNS、文章正文或原始图片。

## 改动

- 首页与标签页封面由 OSS 按实际展示宽度生成 WebP，省去 Vercel 图片服务回源 OSS 的一跳。本地图片继续使用 Next.js 默认图片服务。
- 正文图片使用响应式宽度、懒加载和异步解码；打开图片预览时才请求原图。
- SVG、GIF、其他图片来源及已有签名或处理参数的 URL 保持原样。
- 关闭大量标签链接的自动预加载，文章入口的预加载保留。

使用 OSS 官方的 [图片处理参数](https://www.alibabacloud.com/help/en/oss/user-guide/overview-17/) 和 Next.js 的自定义 Image loader；没有新增依赖。

## 测量与边界

测量日期为 2026-11-04，时区 Asia/Shanghai。网络耗时是单次请求样本，不代表各地访客的固定收益；Mac 和 dev 均存在代理环境，不能当作无代理全国访问结果。

| 样本 | 原路径 | 优化路径 |
| --- | --- | --- |
| `agent-loop-rounds-postmortem/cover.jpeg` 的 640px 封面 | Vercel 图片接口 35,704 字节，1.65 秒 | OSS WebP 29,258 字节，0.20 秒 |
| `my-ai-development-workflow/cover.png` 正文图 | 原始 PNG 2,356,550 字节 | 1440px WebP 105,308 字节，缩小约 95.5% |

真实 Chrome 中，桌面正文实际选中了 768px 图片；封面直接请求 OSS，抽样加载耗时约 0.21–0.25 秒。优化版首页未产生标签 RSC 自动预加载请求。正文压缩图及弹窗原图均成功加载。

博客首页线上响应为 Vercel `HIT`，已静态生成；从 dev 定向访问 Vercel 两个真实 IP 的首字节约 0.59–0.69 秒。从香港访问 Vercel 的样本存在波动，尚未做同一博客经过香港转发的对照，因此本次不据此切换入口。

## 验证

- `pnpm check`：内容校验、TypeScript、ESLint、生产构建通过，生成 79 个页面。
- 在生产构建上执行 `pnpm test:e2e`：11 项通过，包括首页导航、标签、主题、404、安全头、图片打开/关闭与焦点恢复。
- 新增 390px/1280px 图片请求验证：正文先加载处理图，打开预览后才请求原图；另覆盖特殊图片 URL 的保留行为。
- 用户现有 Chrome 标签已验证真实 OSS 图片、预览原图与标签请求。
